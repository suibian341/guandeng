4. cluster_west IS A CONTROL GROUP - AND IT CHANGES THE STORY
==============================================================================
west, stale snapshots : 52 tasks -> 1 failure (1.9%)
other clusters, stale : 209 tasks -> 80 failures (38.3%)
P(<= 1 failures | n=52, p=0.383) = 4.22e-10
Fisher west-vs-others on stale rows: p = 1.81e-08

West's stale rows look identical to everyone else's on every field we
can see:
    lag_min  west 43.2  vs  others 46.7   (MWU p=0.123)
    slots    west 15.2  vs  others 14.4   (MWU p=0.539)
    dur      west 60.6  vs  others 58.6   (MWU p=0.388)
    job_type mix  chi2 p=0.26  |  duration mix chi2 p=0.37 (same mix)

West also has a HIGHER failure rate on fresh rows (4.3%) than on stale
rows (1.9%) - the opposite of the other three clusters.

INTERPRETATION. Age alone is not the mechanism. If an old snapshot were
harmful simply by being old, west would be harmed too. What separates
west is that its snapshot apparently still described the node. The
harmful case is a snapshot that has stopped tracking reality while the
router keeps trusting it. So: 'age >= 20 min' is a PROXY, not the cause.
I cannot see true node capacity in this dataset, so I cannot fully
separate 'stale data causes bad routing' from 'a degrading node both
stops syncing and fails renders'. Both are consistent with everything
above. The operational rule is the same either way - do not route on a
snapshot older than 20 min - and west tells us the rule's false-positive
cost is small and measurable (section 6).

==============================================================================
6. THE FIX, AND WHAT IT IS WORTH
==============================================================================
Decision rule: route to the low-overhead degrade channel when the node
snapshot is older than 20 min. Break-even is
    P(fail) > 10.0 min / 75 min = 13.3%
Observed P(fail) on stale snapshots = 31.0%  ->  2.3x above break-even.
Observed P(fail) on fresh snapshots = 2.2%  ->  below break-even, keep them.

baseline cost of creator wait : 95 failures x 75 min = 7125 min (118.8 h)

OPTION A - refresh the snapshot before routing (block until fresh):
    Refreshed tasks do NOT become failure-free; they join the fresh
    population and inherit its failure rate (2.21%).
    261 stale tasks x 0.0221 = 5.8 expected failures
    expected failures = 14 fresh + 5.8 = 19.8  ->  1483 min
    SAVED                             -> 5642 min (94.0 h) per week
    cost: a few seconds of extra latency per affected task.
    (a naive model crediting A with avoiding all 81 stale failures
     would claim 6075 min and overstate the benefit by 433 min.)

OPTION B - route stale tasks to the degrade channel (10 min each):
    avoids 81 stale failures          -> 6075 min saved
    costs 261 x 10 min               -> 2610 min
    NET                               -> 3465 min saved (57.8 h) per week
    residual 14 fresh failures        -> 1050 min

OPTION B' - same, but exempt a cluster whose stale failure rate is below
break-even. West qualifies (1.9% < 13.3%):
    degrade 209 stale tasks (excluding west) -> 2090 min
    west's 52 stale task stays normal, 1 failure = 75 min
    expected cost = 1125 fresh/west failures + 2090 degrade = 3215 min
    NET                               -> 3910 min saved (65.2 h) per week
    CAVEAT: west's exemption rests on 52 stale rows in one 7-day window.
    Ship the blanket rule first; add the exemption after a second week
    reproduces it.

A beats B by 2177 min/week, so prefer A; keep B as the fallback for
nodes that cannot be re-queried.

SENSITIVITY. Option B nets 81 x F - 261 x D minutes for failure cost F
and degrade cost D. It stays positive while D < 23.3 min, i.e. the
degrade path can be up to 2.3x more expensive than the stated 10 min.

==============================================================================
7. SHIP LIST
==============================================================================
1. Gate routing on snapshot age. Refuse to route on a snapshot older
   than 20 min; re-query the node first, or send the task to the degrade
   channel. This alone removes 85% of observed failures.
2. Emit snapshot age as a first-class scheduling metric, not a debug
   field. It is the strongest signal in the dataset (AUC 0.82) while the
   field actually used for routing is near-useless (AUC 0.54).
3. Alert when the 19-21 min band stops being empty. That band is the
   healthy/degraded boundary; traffic appearing there means the sync
   path is drifting toward the failure regime.
4. Also treat free_slots==0 as a soft signal: 25 tasks, 36% failure
   (vs 9.9% otherwise) - weaker than age, but free.
5. Fix the duplicate emission (47 task_ids emitted twice) and the 40
   blank is_success rows, so the next analysis does not have to caveat them.
